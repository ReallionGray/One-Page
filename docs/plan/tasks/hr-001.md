# Objective

Implement the HR core module: employee records, effective-dated employment, organization placement,
onboarding/offboarding checklists, leave policies/balances/requests, employee documents metadata,
basic attendance import boundary, API authorization, persistence, and contract/integration tests.

# Required behavior

1. Employee and employment records are tenant-scoped and persist through real repositories.
2. Employee identity, employment status, legal entity, department, position, manager, and location
   support effective dates.
3. Required employee data fails fast with typed validation errors.
4. HR commands require the HR permission and applicable organization scope.
5. Sensitive employee fields are not exposed to unauthorized callers.
6. Onboarding and offboarding checklists persist owners, due dates, status, and completion evidence.
7. Leave policies define entitlement/balance behavior; requests validate balance and retain decision history.
8. Leave approval uses the shared authorization boundary; do not create a private authorization system.
9. Employee documents store metadata and a file reference; binary object-storage integration remains
   an explicit adapter boundary, not an in-memory fake presented as production storage.
10. Attendance import validates input and reports row-level errors without silently normalizing bad data.
11. Contract tests and API integration tests cover happy paths, tenant isolation, permission denial,
    sensitive-field denial, invalid input, leave balance failure, and employee offboarding.
